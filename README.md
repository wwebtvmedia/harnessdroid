# Harness Droid

Harness Droid is an experimental Android application that acts as an autonomous agent environment (or "Harness") on your device. Powered by an external LLM Service (such as `com.tree4five.gguf`), the agent can discover and utilize tools exposed by other applications on your device using the Model Context Protocol (MCP) over Android IPC (AIDL).

## Overview

Harness Droid runs a Foreground Service that maintains an autonomous Agent Loop. The agent loop:
1. Receives a user's task request.
2. Queries the system for available Tool Providers (apps that respond to `com.ai.harnessdroid.ACTION_PROVIDE_TOOLS`).
3. Coordinates with a separate LLM application (`com.tree4five.gguf.ACTION_LLM_SERVICE`) to plan a sequence of actions.
4. Executes the tools asynchronously, asking for your permission before taking potentially sensitive actions.
5. Returns a final result.

## Security

Security is a primary concern when giving an LLM access to your device. Harness Droid implements several security measures:

1. **Human-in-the-Loop Permissions**: Before executing any discovered tool, Harness Droid requires explicit user approval. A popup will appear on your screen explaining what tool the agent wants to use and why. The tool will only be executed if you tap **Allow**.
2. **Intent & Service Security**: Tool providers are discovered via explicit Intent actions. The `MockWebBrowserService` (an example built-in tool) is protected with a custom `signature` permission (`com.ai.harnessdroid.permission.BIND_TOOL_PROVIDER`) so that malicious apps cannot blindly bind to it.
3. **Targeted Package Queries**: Following Android 11+ (API 30) security practices, the app explicitly declares in its manifest the intents it intends to query, restricting broader visibility.

## Installation

### Prerequisites

- An Android device running Android 8.0 (API 26) or higher.
- A compatible LLM Provider app installed on your device (must provide the `com.tree4five.gguf.ACTION_LLM_SERVICE` action).
- Developer Options & USB Debugging enabled (if installing via adb).

### Building and Installing

1. **Clone the Repository**:
   ```bash
   git clone <repository_url>
   cd harnessDroid
   ```

2. **Build the App**:
   Using the included Gradle wrapper or Makefile:
   ```bash
   ./gradlew assembleDebug
   # Or using Makefile
   make build-release
   ```

3. **Install on Device**:
   ```bash
   ./gradlew installDebug
   # Or using Makefile
   make local-deploy
   ```

*(Alternatively, you can just flash or install the `.apk` directly to your Android device).*

## User Manual

### Starting the App
Upon launching **Harness Droid**, the background `HarnessService` is immediately started. You will notice a persistent notification indicating that the "Harness Agent Running". This service ensures the agent remains active and handles system-wide tools.

### Main Interface
The user interface features:
- **Chat Interface**: At the center of the screen, you will see the ongoing interaction with the AI assistant. 
- **Input Field**: Type your request (e.g., "Search the web for...") and tap **Run**.
- **Top Menu**:
  - **List Tools**: Injects a prompt asking the agent to list all currently accessible tools.
  - **Clear**: Clears the current chat history.
  - **System Log**: Views the forensic background logs and internal system events (useful for debugging).
  - **View Plan**: Displays the detailed step-by-step internal plan generated by the LLM.
  - **More (⋮)**: Access the **Help** menu and view the application **Version**.

### Approving Tool Executions
When the AI decides to use a tool, you will see a **Permission Required** popup:
- The popup displays the tool name and the reason the AI wants to use it.
- Tap **Allow** to let the AI proceed.
- Tap **Deny** to reject the request, causing the AI to receive a permission denied error.

### Example Tasks
Try using the quick-assist chips below the top bar or inputting your own prompts:
- *"Summarize emails"*
- *"Turn off lights"*
- *"Search deepseek harness"*

## Architecture & Tools

### Built-in Tools
Harness Droid natively includes a few helpful tools:
- `ask_human_for_input`: Allows the LLM to pause and ask the user for clarifying information.
- `get_os_info`: Retrieves basic device information (API level, Model).
- `list_harness_intents`: Discovers what tool provider packages are available on the device.
- `list_installed_apps`: Lists all installed packages.

### Mock Tools
The repository includes a `MockWebBrowserService` which acts as a simulated tool provider for testing purposes. It exposes a `web_search` tool through MCP.

### Tool Provider Protocol
Third-party apps can become tools for the harness by:
1. Creating an exported service with an intent filter for `com.ai.harnessdroid.ACTION_PROVIDE_TOOLS`.
2. Implementing the `IToolProviderService` AIDL interface.
3. Replying with a standard Model Context Protocol (MCP) JSON-RPC structure.
